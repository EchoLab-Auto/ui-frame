# @echolab-auto/ui-frame 设计规范

> 本文档是 ui-frame 的**视觉与排布设计规范**——把「好界面」的判断标准固化为可执行、可检查的规则：视觉层次、对齐、间距、图标与触控，全部落在本库的新拟态语言与 Token 体系上。读者：实现与调整本库界面的开发者（含 AI Agent）。写新组件、排布界面或绘制图标前先读本文；实现层原则见 [设计理念](./design-philosophy.md)，阴影与动效机制见 [动画效果](../user/animation.md)，键盘与焦点行为见 [交互效果](../user/interaction.md)。

---

## 一、八条设计原则

视觉决策遇到分歧时，回到这八条上裁决（前四条是底线，不可让步）：

| 原则       | 一句话                 | 在本库的落点                                           |
| ---------- | ---------------------- | ------------------------------------------------------ |
| **有目的** | 每个元素都要有存在理由 | 删除装饰性阴影与渐变；台阶高度、留白、色阶都是功能语言 |
| **自主**   | 让人按自己的方式操作   | 不锁定流程：可取消、可返回、错误可逆；弹层默认不阻断   |
| **负责**   | 一切以使用者利益为先   | 破坏性操作需二次确认；无障碍不降级；不暗藏自动行为     |
| **熟悉**   | 建立在人们已知之上     | 沿用平台惯例与本库既有形态，不发明新手势、新交互       |
| **灵活**   | 适配不同情境           | 三级级联配置；Token 可覆盖；双主题 / RTL / 触屏全支持  |
| **简洁**   | 清晰直接，删除多余     | 渐进披露；默认即可用；一屏一个主任务                   |
| **打磨**   | 每个细节都在意         | 对齐到网格、光学修正、状态齐全、过渡曲线统一           |
| **愉悦**   | 保留人的温度           | 弹簧回弹与浮雕光影——克制、服务于操作，不喧宾夺主       |

## 二、视觉层次：台阶高度是第一语言

新拟态界面没有边框与分割线，**层次几乎全部由「物体浮起的程度」表达**。`elevation`（台阶高度）因此是本库的第一视觉语言，与字号、色阶、留白共同构成层次手段。

### 2.1 台阶语义表

| 台阶        | 语义            | 典型载体                               |
| ----------- | --------------- | -------------------------------------- |
| `0` 平齐    | 与背景同面      | 列表分节、表单分组、无边框区块         |
| `+1` ~ `+2` | 静置承载面      | 卡片（默认 `2`）、面板、列表容器       |
| `+2` ~ `+4` | 可交互的凸起物  | 按钮、分段控件选中段、开关滑块         |
| `-1` ~ `-2` | 内嵌槽位        | 输入框、分段控件轨道、进度条轨道       |
| `-3` ~ `-4` | 深槽 / 按下瞬态 | 开关轨道、按压中的按钮、拖拽中的目标区 |

**一屏之内台阶级数不超过 3**——级数一多就变成「泡泡堆叠」，层次感反而消失。

### 2.2 层次手段的组合纪律

- 层次变化先从**一个维度**开始（如只改字号或只升一级台阶）；不够再加第二个维度
- 文本层次用「字号 + 字重 + 文本四级色」组合表达，不用斜体或下划线
- 颜色的对比度是稀缺资源：主色（`--nm-primary-color`）只留给全屏最重要的一个动作

### 2.3 眯眼测试

**眯起眼睛看你的界面**：视线最先落到哪里？那里应当是本屏最重要的内容。若先落到装饰物、背景或次要元素上，层次就是错的。同样，眯眼后所有元素会退化为大小不一的色块，色块的主次即真实的层次——这是最快的自检手段。

### 2.4 阅读顺序

人从**上到下、从起始侧到末尾侧**扫视界面（RTL 语言自动镜像）。因此：

- 最重要的内容放在顶部与起始侧
- 操作与提示跟随内容阅读流（先内容后操作），而不是固定在角落
- 不手写方向值——用逻辑属性与 `nm-rtl-*` mixin，让镜像由系统接管

## 三、对齐与光学修正

### 3.1 对齐是关系表达

对齐不只是整齐——**人对齐的元素被默认为相关**。所以：

- 想表达「这是一组」→ 轴线对齐（左缘、基线或中心）
- 想表达「这是下层」→ 缩进；缩进是层级的语法，缩进量从间距刻度取（推荐 `--nm-spacing-md` 16px 起步）
- 一律对齐到 8px 网格（`--nm-spacing-sm` 的倍数）；4px（`--nm-spacing-xs`）只用于内部紧凑微调

### 3.2 光学中心而非几何中心

非对称图形按几何居中会显得偏移——**视觉重量大的一侧要向外让位**。修正方法：把微调量做进图标资产的 **padding**（如下部多 2px），此后照常几何居中即可自动获得光学居中；修正一次、处处正确，且不会在每次使用时重调。

```
几何居中：下重上轻的形状「看起来偏下」
光学居中：形状上移 1–2px（做进 padding）→ 视觉平衡
```

### 3.3 常见对齐陷阱

- **图标与文字**：按**视觉重心**对齐（通常略高于基线），而不是与基线死对齐
- **数字列**：金额、统计数字**右对齐**（让个位对齐）；普通文本一律左对齐
- **圆角容器内的元素**：内容与容器的视觉内缘等距留白，内距取刻度值（卡片内距默认 `--nm-spacing-lg`）
- 光学修正的量级很小（1–3px），但缺失时「歪」会被一眼看出

## 四、间距与分组

### 4.1 间距刻度

一切间距取自刻度表，**禁止魔法数字**：

| Token              | 值   | 典型用途               |
| ------------------ | ---- | ---------------------- |
| `--nm-spacing-2xs` | 2px  | 图标与角标、紧密叠加   |
| `--nm-spacing-xs`  | 4px  | 行内元素之间、紧凑间隙 |
| `--nm-spacing-sm`  | 8px  | 图标与文字、组内元素   |
| `--nm-spacing-md`  | 16px | 表单行距、语句块之间   |
| `--nm-spacing-lg`  | 24px | 卡片内距、区块内分组   |
| `--nm-spacing-xl`  | 32px | 区块之间               |
| `--nm-spacing-2xl` | 40px | 页面级分区             |
| `--nm-spacing-3xl` | 48px | 页面级分区（大屏）     |

### 4.2 接近性：距离表达关系

**间距是最诚实的分组工具**：两个元素的间距告诉人它们有多亲。规则：

- **组内间距 < 组间间距**，且至少差一个刻度档（如组内 8、组间 16 或 24）
- 想让元素「脱离」当前分组 → 加大它与邻元素的距离，而不是给它描边
- 表达「这些不相关」→ 拉开距离或引入分隔物

### 4.3 分组手段的优先级

新拟态没有描边语言，分组按以下优先级选择：

```
留白 ＞ 凹陷容器 ＞ 卡片 ＞ 分隔线
```

- **留白**：默认手段，零成本、最安静
- **凹陷容器**：需要视觉容器时——把「槽」做出来（`nm-inset`），内容放进槽里
- **卡片**：当这组内容需要独立存在感、可拖拽或可折叠时
- **分隔线**：最后手段（`NeumorphismDivider`），只在密集列表里使用

### 4.4 内距的对称纪律

卡片、面板的四周内距应**对称**，或「上下 ≤ 左右」（如 header 用 16 / 24、body 用 24）。内距不得小于内容自身的组内间距——否则容器看起来「勒着」内容。

## 五、渐进披露

界面初始只呈现**起步所需**，进阶内容渐进展开：

- 超出 5 项的同类信息 → 先展示核心项，其余折叠（`Collapse`）或滚动
- 次级操作 → 收进 `Dropdown` 或「更多」菜单，而不是平铺为对等按钮
- 详情与表单 → 由 `Drawer` / `Modal` 承载，保持主界面安静
- 高级选项 → 默认收起，但**默认值必须可用**——渐进披露不等于把功能藏到没人找得到

**反模式**：

- 默认全展开的树与面板（视觉噪音）
- 所有操作平铺为同级按钮（没有主次）
- 用折叠隐藏**必要**信息（价格、风险提示）——渐进披露只藏进阶内容，不藏决策信息

## 六、一致性

一致性让「学过的东西」可以迁移。四个维度必须同时对：

| 维度     | 要求                                                                     |
| -------- | ------------------------------------------------------------------------ |
| **几何** | 同语义同取值：圆角、台阶级数、间距、尺寸档一律从 Token 取                |
| **状态** | 同角色组件提供同一套状态（hover / active / focus / disabled / selected） |
| **文案** | 同一动作同一措辞（「保存」不要在某处叫「提交」）                         |
| **行为** | 同交互同一响应（如所有浮层：Esc 关闭、点击外部关闭）                     |

### 6.1 圆角语义表

| Token                     | 值   | 语义                                     |
| ------------------------- | ---- | ---------------------------------------- |
| `--nm-border-radius-xs`   | 4px  | 内嵌小元素（角标、小标签内衬）           |
| `--nm-border-radius-sm`   | 8px  | 小控件、浮层内元素、工具提示             |
| `--nm-border-radius-md`   | 16px | 标准控件（按钮默认、输入框、下拉面板）   |
| `--nm-border-radius-lg`   | 24px | 卡片默认、模态                           |
| `--nm-border-radius-xl`   | 32px | 大容器、全屏面板                         |
| `--nm-border-radius-full` | 胶囊 | 标签、徽章、圆形按钮（`shape="circle"`） |

规则：**嵌套容器「外 > 内」**（外卡 24 配内卡 16 或 8）；两层取同值会显得「糊在一起」。

### 6.2 变体纪律

`variant` / `size` / `shape` 是有限的意图集合——选择最接近意图的档位，**不要为单个页面发明新变体**。需要新视觉效果时先问：是既有变体的组合问题，还是确实缺一个语义档位？只有后者才允许新增。

## 七、排版

### 7.1 字号体系

| 用途     | Token                               | 值                         |
| -------- | ----------------------------------- | -------------------------- |
| 辅助信息 | `--nm-font-xs` / `--nm-font-sm`     | 11 / 12px                  |
| 正文默认 | `--nm-font-base`                    | 14px                       |
| 强调正文 | `--nm-font-lg` / `--nm-font-xl`     | 15 / 16px                  |
| 区块标题 | `--nm-font-2xl` / `--nm-heading-h4` | 18px                       |
| 页面标题 | `--nm-heading-h3` ~ `h1`            | 22 / 28 / 34px（等比阶梯） |

### 7.2 字重与细字禁令

库只提供 400 / 500 / 600 / 700 四档字重。**禁止使用更细的字重（Light/Thin）**：新拟态底色是低对比灰面，细字在其上直接失去可读性；数字与标签若需要弱化，用**文本色阶**而不是减字重。

### 7.3 文本四级色与行高

- 文本层次一律用四级色 Token：`primary`（正文）→ `secondary`（辅助）→ `placeholder`（占位）→ `disabled`（禁用）
- 行高配套：`tight` 1.25（标题）/ `normal` 1.5（正文）/ `relaxed` 1.75（长文）
- 标题不跳级；单行文本宽度控制在 45–75 字符（中文约 24–40 字）

## 八、图标

### 8.1 设计：单一概念、熟悉隐喻

- 一个图标表达**一个**概念；用大众化隐喻（下载 = 向下箭头入托盘），不做需要学习的自创符号
- 图标**不承载唯一信息**：关键含义必须有文字或 `aria-label` 伴随
- 界面装配优先使用矢量图标资产（SVG）；`icon` 属性的字符 / emoji 输入属于兼容回退，不作为默认设计选择

### 8.2 一致性：三个统一

同一界面里的全部图标必须统一：

1. **描边粗细**：一套界面只用一个线宽（如 1.5px 或 2px）
2. **视觉尺寸**：尺寸阶梯取 `16 / 20 / 24px`（行内跟随文字用 16、工具条 20、独立动作 24）；按视觉重量微调——方形图标看起来比圆形大，必要时缩小 1–2px 让它们「看起来一样大」
3. **透视与风格**：线框一套、填充一套，不混用

### 8.3 图标与文字：重量匹配

图标与相邻文字**粗细相匹配**（文字 Regular 配 1.5px 线宽、Semibold 配 2px），否则会出现「字在喊、图标在说悄悄话」的失衡。

### 8.4 光学对齐（图标必备工艺）

- 非对称图标（播放三角、下载箭头等）必须做**光学居中**，修正量做进图标 padding（见 §3.2）
- 图标与文字并排时，按视觉重心对齐而非基线对齐
- 圆形 / 胶囊按钮内的图标同样适用——几何居中会让某些图标「下沉」

### 8.5 可点击图标的触控目标

图标本体的尺寸与**可点区域**是两回事：24px 的图标，可点区域必须补足到 **≥ 44×44px**（用 `min-height` / `min-width` 或透明 padding 扩展命中区）。密集列表中的行内图标按钮允许 32px 紧凑档，但**仅限鼠标环境**；触屏（`pointer: coarse`）下由全局约定强制回到 44px。

## 九、触控目标与交互反馈

### 9.1 尺寸与间距

- 交互元素可点区域 **≥ 44×44px**（`--nm-button-min-height-md: 44px` 即此基准；触屏下全局强制）
- 相邻独立可点元素之间 **≥ `--nm-spacing-sm`（8px）**，非紧凑场合取 `--nm-spacing-md`（16px）或以上——避免误点
- 尺寸档位语义：`sm 32`（仅鼠标密集场景）/ `md 44`（默认）/ `lg 56`（主要动作、大屏触控）

### 9.2 状态五件套

每个可交互元素必须定义完整五态，缺一即不合格：

| 状态            | 视觉要求                                                          |
| --------------- | ----------------------------------------------------------------- |
| 默认            | 静置台阶                                                          |
| `hover`         | 微上浮（-2px 或阴影加深）——**只在指针设备生效**（`hover: hover`） |
| `active`        | **按下 = 凹陷**（物理隐喻：压下去），用 `nm-active-press`         |
| `focus-visible` | 2–3px 主色光环（`.nm-focus-ring`），键盘可见、鼠标不打扰          |
| `disabled`      | 文本降为 `--nm-text-disabled`，**不再响应任何状态变化**           |

### 9.3 反馈的两条原则

- **反馈发生在操作点上**：按下的按钮自己凹陷，而不是在页面别处弹提示
- **反馈必须可见**：没有可见反馈的「已生效」等于没有生效——长动作要有进行态（`Spinner` / `Progress`），完成要可感知（`Toast` 或状态变化）

## 十、主题与适配

- **颜色只能来自 Token**：任何硬编码色值视为缺陷；暗色主题无需手工调色——阴影配比重排由 Token 层完成（见 [动画效果](../user/animation.md)§台阶高度模型）
- **暗色对等**：新组件必须同时在 `light` / `dark` 下逐项自检；暗色的阴影可见度与亮色并不对称
- **RTL**：方向性图标（箭头、进度）与浮层方位需镜像——用逻辑属性与 `nm-rtl-*` mixin
- **动效可达性**：`prefers-reduced-motion` 下所有位移与过冲降级（全局已有支持，新动画必须复查）
- **响应式**：断点 `576 / 768 / 992 / 1200 / 1400px`（`nm-screen-*` mixin）；竖屏 < 768px 按触屏规则收紧（44px 命中区、横滚容器、hover 不触发）

## 十一、检查清单

> 与 [develop.md](./develop.md) 的「检查清单汇总」配合使用；本节只覆盖**视觉与排布**维度。

### 层次与布局

```
□ 眯眼测试：第一眼落在最重要的内容上
□ 一屏台阶级数 ≤ 3；层次手段 ≤ 2 个维度组合
□ 间距全部取自刻度表，无魔法数字
□ 组内间距 < 组间间距（差至少一档）
□ 缩进表达从属；对齐表达相关；对齐到 8px 网格
□ 非对称元素做过光学居中；修正做进 padding
```

### 排版与图标

```
□ 字重 ≥ 400，无细字使用
□ 文本层次用四级色 Token（primary / secondary / placeholder / disabled）
□ 全部图标统一描边粗细与视觉尺寸，无 emoji 充当界面图标
□ 图标与相邻文字粗细匹配；图标未承载唯一信息
□ 图标按钮可点区域 ≥ 44×44px
```

### 交互与主题

```
□ 五态齐全：默认 / hover / active / focus-visible / disabled
□ 按下效果 = 凹陷（nm-active-press）
□ 反馈发生在操作点且可见
□ 亮色 / 暗色双主题自检通过，无硬编码色值
□ RTL 镜像正确（方向性图标与浮层方位）
□ prefers-reduced-motion 下动效降级正常
```
