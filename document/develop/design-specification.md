# 元 UI 设计规范

> **定位**：ui-frame 项目的**元 UI 设计规范（meta-norm）**——把 Apple 官方设计材料（Human Interface Guidelines 与 WWDC 设计课程，清单见文末「参考」）中的设计要点，整理为「什么是好界面」的**判断标准与要求**，覆盖设计原则、视觉层次、对齐、间距与分组、渐进披露、一致性、排版、图标、触控反馈与主题适配。它是**元级**规范：只定义要求、**不绑定任何具体实现**——不指定组件、代码、设计 Token 取值或设计风格，对 ui-frame 与其它 UI 系统同样适用；**规范与实现分离**，各系统按本规范做设计决策，并在自身的实现层文档中声明落地映射（ui-frame 的映射见 [设计理念](./design-philosophy.md)）。读者：做界面设计、实现与评审的开发者（含 AI Agent）。

---

## 一、八条设计原则

视觉决策遇到分歧时，回到这八条上裁决（前四条是底线，不可让步）；原则体系整理自 Apple Design principles / WWDC《Principles of great design》：

| 原则       | 一句话                 | 判断标准                                                  |
| ---------- | ---------------------- | --------------------------------------------------------- |
| **有目的** | 每个元素都要有存在理由 | 新增任何元素前能回答「它解决什么问题」；纯装饰默认拒绝    |
| **自主**   | 让人按自己的方式操作   | 操作可取消、可返回、错误可逆；不强制流程、不阻断用户      |
| **负责**   | 一切以使用者利益为先   | 破坏性操作需确认；无障碍不降级；不暗藏自动行为            |
| **熟悉**   | 建立在人们已知之上     | 沿用平台与行业的既有惯例，不发明需要学习的交互            |
| **灵活**   | 适配不同情境           | 适配不同尺寸、主题、语言（含 RTL）与输入方式（触控/鼠标） |
| **简洁**   | 清晰直接，删除多余     | 一屏一个主任务；次要信息渐进披露而非平铺                  |
| **打磨**   | 每个细节都在意         | 对齐、间距、状态、动效全部有一致标准，无例外              |
| **愉悦**   | 保留人的温度           | 质感与动效克制、服务于操作，不喧宾夺主                    |

## 二、视觉层次

任何界面都要能回答：「第一眼看哪里、第二眼看哪里」。建立层次的可用手段，按优先级：

1. **位置**——重要内容放在阅读流的前部（上→下、起始侧→末尾侧）
2. **尺寸与字重**——更大、更重的元素天然更靠前
3. **对比与色阶**——高对比吸引注意；弱化次要信息用降色阶，而非缩字号
4. **空间**——独占的留白赋予元素「呼吸权」，即重要性
5. **纵深层级**——浮起/压入（阴影、材质、叠层等）是方向性最强的信号，慎用

组合纪律：

- 层次变化先从**一个维度**开始；不够再加第二个维度——同时改动多个维度会让界面失去秩序
- 一屏内纵深层级不超过 3 级
- 高饱和与主色是最稀缺的资源，只留给全屏最重要的一个动作

**眯眼测试**（最快的自检）：眯眼看界面，视线最先落在哪里，那里就是实际视觉重心——它应当是本屏最重要的内容。若先落到装饰物或次要元素上，层次就是错的。

## 三、对齐与光学修正

### 3.1 对齐是关系表达

对齐不只是「整齐」——**人对齐的元素被默认为相关**。因此：

- 表达「同组」→ 轴线对齐（左缘、基线或中心轴）
- 表达「从属」→ 缩进；缩进量来自统一刻度
- 表达「无关」→ 不对齐或拉开距离
- 一切几何量（对齐偏移、缩进、间距）取自系统的刻度体系，禁止随手取值

### 3.2 光学中心优先于几何中心

非对称图形按几何居中会显得偏移——视觉重量大的一侧要向外让位。修正工艺：把微调量（1–3px 量级）做进图形资产的内边距，此后按几何居中即可自动获得光学居中——修正一次，处处正确。

### 3.3 常见陷阱

- 图标与文字并排：按**视觉重心**对齐，而非与基线死对齐
- 数字列：金额、统计数字右对齐（数位对齐）；普通文本左对齐
- 图形与容器：内容与容器的视觉内缘等距留白；容器的内距不得小于内容自身的组内间距
- 修正量级很小（1–3px），但缺失时「歪」会被一眼看出

---

## 四、间距与分组

### 4.1 间距刻度

**一切间距必须来自可枚举的刻度体系，禁止魔法数字。** 刻度的建立方法（业界共同实践）：

- **推荐**以 4 或 8 为基数建立阶梯（示例值：2 / 4 / 8 / 16 / 24 / 32 / 40 / 48——具体取值由各系统自定）
- 小间隔取小刻度、大分区取大刻度；跨级使用必须有理由
- 同一系统中所有间距、内距、偏移消费同一刻度，保证全局节奏一致

### 4.2 接近性：距离表达关系

**间距是最诚实的分组工具**：两个元素的间距告诉人它们有多亲。

- **组内间距 < 组间间距**，且至少差一个刻度档
- 让元素「脱离」当前分组 → 加大它与邻元素的距离，而不是给它描边
- 表达「不相关」→ 拉开距离或引入分隔物

### 4.3 分组手段的优先级

按「视觉噪音从低到高」选择，优先取噪音最低者：

```
留白 / 距离 ＞ 背景分区（底色或内凹面） ＞ 显式容器（卡片） ＞ 分隔线
```

分隔线是最后手段，只在留白不足以分组（如密集列表）时使用。

### 4.4 内距纪律

容器四周内距应**对称**，或「上下 ≤ 左右」。内距必须大于等于容器内元素的组内间距——否则容器会「勒住」内容。

## 五、渐进披露

界面初始只呈现**起步所需**，进阶内容渐进展开：

- 同类信息超过一屏承载量 → 先展示核心项，其余折叠或滚动可达
- 次级操作 → 收进菜单或「更多」，不平铺为对等按钮
- 详情与编辑 → 由浮层（抽屉 / 模态）承载，保持主界面安静
- 高级选项默认收起，但**默认值必须可用**——渐进披露不等于隐藏功能

反模式：

- 默认全展开的树与面板（视觉噪音）
- 所有操作平铺为同级按钮（没有主次）
- 用折叠隐藏**必要**信息（价格、风险、法律提示）——只藏进阶内容，不藏决策信息

## 六、一致性

一致性让「学过的东西」可以迁移。四个维度必须同时对：

| 维度     | 要求                                                              |
| -------- | ----------------------------------------------------------------- |
| **几何** | 同语义同取值：圆角、层级、间距、尺寸档位全部来自同一刻度体系      |
| **状态** | 同角色元素提供同一套状态：默认 / 悬停 / 按下 / 焦点 / 禁用 / 选中 |
| **文案** | 同一动作同一措辞（「保存」不要在某处叫「提交」）                  |
| **行为** | 同交互同一响应（如所有浮层：Esc 关闭、点击外部关闭）              |

**几何嵌套规则**：嵌套容器「外大内小」（外层圆角大于内层圆角）——两层同值会显得「糊在一起」。

**变体纪律**：既有的变体（尺寸、形态、层级）是有限的意图集合——选择最接近意图的档位，**不为单个页面发明新变体**。需要新视觉效果时先问：是既有手段的组合问题，还是确实缺一个语义档位？只有后者才允许新增。

## 七、排版

### 7.1 字号阶梯

字号体系应是**可枚举的等比阶梯**（常见 1.2–1.25 倍率），并为每级定义用途（辅助信息 / 正文 / 强调 / 标题……）。禁止随手字号。平台惯例的最小字号是底线（如 iOS 正文默认 17pt、macOS 13px），不得低于。

### 7.2 字重

- 可用字重收敛为有限档位（常规 / 中等 / 半粗 / 粗体）
- **低对比表面上禁止细字重**（Light / Thin）：灰面细字直接失去可读性；弱化文字应降色阶，而非减字重

### 7.3 文本层次与行高

- 文本层次 = 字号 + 字重 + 色阶的组合；色阶一般 3–4 级（正文 / 次要 / 占位 / 禁用）
- 行高按文本角色配套：标题紧凑、正文适中、长文宽松
- 标题层级不跳级；单行文本宽度控制在 45–75 字符（中文约 24–40 字）——超宽会伤阅读效率

## 八、图标

### 8.1 设计与语义

- 一个图标表达**一个**概念；使用大众化隐喻，不做需要学习的自创符号
- 图标**不承载唯一信息**：关键含义必须有文字或无障碍标签伴随
- 界面控件优先使用矢量图形资产；字符与 emoji 仅作内容表达，不充当控件图标

### 8.2 三个统一

同一界面内全部图标必须统一：

1. **描边粗细**——同一套界面只用一个线宽
2. **视觉尺寸**——尺寸阶梯可枚举（如 16 / 20 / 24）；方形与圆形图标按视觉重量微调 1–2px
3. **风格与透视**——线框一套、填充一套，不混用

### 8.3 与文字的关系

- **重量匹配**：图标线宽与相邻文字的字重相匹配，否则出现失衡（「字在喊、图标在说悄悄话」）
- **光学对齐**：非对称图标必须做光学居中（见 §3.2）；与文字并排时按视觉重心对齐

### 8.4 可点击图标

图标尺寸 ≠ 可点区域。可点区域必须补足到触控最低要求（见 §9.1），用透明扩展或尺寸约束实现。

---

## 九、触控目标与交互反馈

### 9.1 尺寸与间距

- **可点区域 ≥ 44×44 逻辑像素**——行业共识的触控最低要求（iOS 44pt、Android 48dp 为同量级的两个代表）；触屏环境不可妥协
- 相邻独立可点元素之间保留足够间隔（≥ 8px；非紧凑场合更大），避免误点
- 尺寸档位可收敛为三档：紧凑（鼠标专用）/ 标准（默认）/ 大（主要动作与触控）

### 9.2 状态五件套

每个可交互元素必须定义完整状态，缺一即不合格：

| 状态 | 要求                                               |
| ---- | -------------------------------------------------- |
| 默认 | 静置态                                             |
| 悬停 | 有可感知的反馈；**只在指针设备生效**（触屏不触发） |
| 按下 | 即时反馈（位移 / 形变 / 颜色），响应时间要短       |
| 焦点 | 键盘操作可见焦点环；鼠标操作不打扰                 |
| 禁用 | 降低强调，且**不再响应任何状态变化**               |

### 9.3 反馈原则

- **反馈发生在操作点上**——按下的按钮自己变化，而不是在别处弹提示
- **反馈必须可见**——没有可见反馈的「已生效」等于没有生效：长动作要有进行态，完成要可感知

## 十、主题与适配

- **颜色来自体系**——所有颜色取值来自系统的语义色阶（且具备暗色变体）；散落的硬编码色值视为缺陷
- **暗色对等**——所有界面必须在暗色下逐项自检；暗色下的对比与层次可见度同亮色并不对称
- **RTL**——方向性图标（箭头、进度）与浮层方位需镜像；使用逻辑方向概念，不写死左右
- **动效可达性**——尊重「减少动态效果」偏好；位移与过冲动效可降级
- **响应式**——适配不同尺寸与尺寸类别（窗口、横竖屏、分屏）；断点由系统统一管理，不为单页面特设

## 十一、检查清单

> 设计、实现与评审时逐项过堂；本清单只覆盖视觉与交互的通用判断标准，不涉及任何实现细节。

**层次与布局**

```
□ 眯眼测试通过：第一眼落在最重要的内容上
□ 一屏内纵深层级 ≤ 3；层次变化不超过 2 个维度组合
□ 间距全部来自刻度体系，无魔法数字
□ 组内间距 < 组间间距（至少差一档）
□ 缩进表达从属、对齐表达相关；几何量取自刻度
□ 非对称图形做过光学居中（修正做进资产内边距）
```

**排版与图标**

```
□ 字号、字重来自枚举阶梯；不低于平台最小字号
□ 低对比表面无细字重
□ 文本层次用「字号 + 字重 + 色阶」组合表达
□ 全部图标统一线宽与视觉尺寸；emoji 与字符未充当控件图标
□ 图标与文字重量匹配；图标不承载唯一信息
□ 可点击图标的可点区域 ≥ 44×44
```

**交互与主题**

```
□ 状态五件套齐全（默认 / 悬停 / 按下 / 焦点 / 禁用）
□ 反馈发生在操作点且可见
□ 亮暗两套主题自检通过；无硬编码颜色
□ RTL 镜像正确；减少动效偏好下动效可降级
□ 尺寸与输入方式（触控 / 鼠标）变化不破坏以上任何一条
```

---

## 十二、元规范的消费方式

本规范只规定要求、不规定实现。任何 UI 系统消费本规范的标准姿势：

1. **声明落地映射**——在系统自身的实现文档中，逐条声明「本规范的要求 → 本系统的具体承载物」（例如：间距刻度 → 系统的 spacing 取值表；状态五件套 → 组件的交互态实现）
2. **设计与评审以此为据**——新增组件、页面、图标时，以第十一节检查清单逐项过堂
3. **例外必须显式**——确需偏离某条要求时，记录理由与范围，而不是默默违反

> 本仓库的 ui-frame 是本规范的首要落地实现：实现层映射见 [设计理念](./design-philosophy.md)；Token 与组件细节见各组件的用户文档。
